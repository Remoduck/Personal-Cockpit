📦 Repository ("repo")

A project's folder + its entire history, stored by Git.Your spellbook — every spell and every past edit, bound together.

💾 Commit

A saved snapshot of changes with a message. The atomic unit of history.Casting a spell into the book with a note on what it does — permanent and labelled.

🌿 Branch

A movable pointer to a line of commits inside one repo.A separate page you write on so you don't scribble over the master page (main).

🍴 Fork

Your personal server-side copy of someone else's repo.Photocopying Dumbledore's spellbook so you can experiment freely.

📥 Clone

Downloading a repo to a machine.Copying the whole spellbook onto your desk at home.

🛰️ Remote

A saved address a repo syncs with (origin, upstream, enterprise…).An owl's destination — a saved address you send letters to.

📜 Pull Request

A formal request to merge your branch. A SEPARATE step from pushing, done in the browser.Asking the gods/librarian to accept your pages into the official book.

🔀 Merge

Combining one branch's commits into another.Copying your page's spells into the master page.

⚔️ Merge conflict

When two branches changed the same lines and Git can't auto-decide.Two wizards edited the same spell differently — you must choose the final wording.

📌 HEAD

A pointer to "where you are right now" (usually the tip of your current branch).The bookmark showing which page you're currently writing on.

🏷️ Tag / Release

A named marker on a commit, often a version (v1.0).A wax seal marking an important, finished edition.

📦 .gitignore

A file listing things Git should NOT track (secrets, build junk).The Room of Hidden Things — stuff you deliberately keep out of the book.

🌿 Branch — a line of work

Lives inside one repo. Switch with git checkout name. Your everyday default.

Use when: starting any feature/fix in a repo you can push to.A separate page in your own spellbook.

🍴 Fork — a whole copy

A separate repo under your account. Has its own branches.

Use when: you lack push access to the original but want to contribute (fork → branch → PR).Your photocopy of someone else's book.

🪵 Worktree — two folders, one repo

Check out a second branch into a second folder, sharing the same history/remotes.
git worktree add ../hotfix feature/add-dsgvo
Use when: you need two branches live at the same time (compare builds, urgent fix mid-feature) without stashing.Magically duplicating your desk so two pages are open at once.

They stack, not compete:

FORK (a whole repo copy) └── BRANCH (a line of work) ×many └── WORKTREE (an extra folder for that branch) ×optional

Quick chooser:

Repo I can push to? → just make a branch.
Repo I can't push to? → fork it, branch inside, open a PR.
Need two branches open simultaneously? → add a worktree.

Two copies, two remotes. Pull FROM upstream to stay current; push TO origin to save your work. 🪄

upstream (original: CVE-1990-0001) ◄── you PULL new changes FROM here │ │ (you forked it) ▼ origin (your fork: Remychng) ──► you PUSH your work TO here │ ▼ Pull Request ──► proposes your changes back UP to upstream

🍴 origin = your fork

The copy you cloned: Remychng/regulation-explorer. You push your branches here. Created automatically when you clone.Your personal photocopy in the dorm.

🔱 upstream = the original

The repo you forked from: CVE-1990-0001/regulation-explorer. You pull new changes from here to stay current. You add it yourself by convention.The official Hogwarts library spellbook.

❓ Why bother?

Your fork is frozen at fork-time. The original keeps moving as teammates merge PRs. upstream lets you catch up so your work doesn't drift or conflict.The library keeps adding spells — upstream copies them into your book.

Step by step

1. See current remotes
git remote -v
Only origin shows at first.
2. Add upstream
git remote add upstream https://github.com/CVE-1990-0001/regulation-explorer.git
Trains a second owl. 🦉
3. Confirm both exist
git remote -v   # now shows origin AND upstream
4. Stay up to date (whenever you start work)
git checkout main
git pull upstream main      # newest changes from the original
git push origin main        # (optional) update your fork too

🧭 One sentence to remember

Pull FROM upstream to stay current · push TO origin to save your work · open a PR to send changes back up to upstream.

🔑 SSH key

Proves who you are when pushing/pulling. A key pair: a secret private key (never share) and a public .pub you give the server. Each server needs its own.
ssh-keygen -t ed25519 -C "you@email"
cat ~/.ssh/id_ed25519.pub   # give this to GitHub
ssh -T git@github.com       # test
A building pass — your private key is the magic word only you know; the public key is the lock the castle installs. Camp Jupiter won't accept Camp Half-Blood's pass.

✍️ GPG key

Proves you really made a commit by cryptographically signing it → the green "Verified" badge. Authentication (SSH) ≠ authorship (GPG).
git config --global commit.gpgsign true
Your personal wax seal pressed onto each page, proving no imposter wrote it.

🌐 HTTPS + PAT

The other way to connect (vs SSH). Uses a URL like https://github.com/... and a Personal Access Token instead of a password.Entering through the front gate with a signed permission slip (token) rather than a secret side-passage key (SSH).

🔢 2FA

Two-Factor Authentication: password + a second code (app/key). Often required on Enterprise.Needing both a password AND your wand to enter — one alone won't do.

🆚 SSH vs HTTPS — which?

SSH: set up a key once, no typing tokens after. Great for machines you control (your VM). HTTPS: easier through firewalls/proxies, uses a token. Both do the same job.Side-passage (SSH) vs front gate (HTTPS) — both get you into the castle.

⚠️ Golden rule of keys

Only ever share the .pub (public) half. The file WITHOUT .pub is your secret — never paste it anywhere.Never tell anyone your secret magic word.

The terminal is for git commands. The browser is for https:// links. Don't mix them. 🪄

🌿 Branches
git branch -aList all branches (local + remote).
git checkout <branch>Switch to a branch.
git checkout -b <new>Create AND switch to a new branch.
💾 Saving work
git add .Stage all changes for the next commit.
git commit -m "message"Save a snapshot with a note.
git stashTemporarily shelve uncommitted work; git stash pop brings it back.
🛰️ Remotes & syncing
git remote -vShow saved addresses (read-only, safe).
git remote add <name> <url>Add a new destination (e.g. enterprise).
git remote set-url <name> <url>Fix an existing remote's address.
git push <remote> <branch>Upload a branch.
git pullFetch + merge the latest from the remote.
git fetchDownload updates WITHOUT merging (safe to inspect first).
🪵 Worktrees
git worktree add ../folder <branch>Check out another branch in a second folder.
git worktree listShow all worktrees.
🐙 GitHub CLI (gh) — talks to GitHub itself
gh auth loginLog in to GitHub from the terminal.
gh pr createOpen a Pull Request without the browser.
gh pr listList PRs (shows each branch).
gh repo clone owner/repoClone by name.
Note: git manages history; gh manages GitHub things (PRs, issues, repos). Different tools.

"What should I do?" — follow the questions

Q: Does my work belong on Enterprise? ├─ YES → do everything in the VM, git push enterprise, PR on deutsche-boerse.de. └─ NO (github.com) → laptop is fine, git push origin, PR to upstream. Q: Do I have push access to the repo? ├─ YES → make a branch, commit, push, open a PR. └─ NO └─ Fork it → branch in your fork → push → PR to the original. Q: Do I need two branches checked out at once? ├─ YES → git worktree add a second folder. └─ NO → just git checkout between branches. Q: Files don't show in the VS Code sidebar after cloning? └─ You cloned but didn't OPEN the folder → code . or File → Open Folder. Q: Push rejected — "Permission denied (publickey)"? └─ Your SSH key isn't on that server → add the .pub in Settings → SSH keys. Q: Want the green "Verified" badge on commits? └─ Set up a GPG key and enable commit.gpgsign.
